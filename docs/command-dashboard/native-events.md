# Native Discord events

The latest contract is saved in `native-events-clarification.md`. Native Guild Scheduled Events have no events-section channel ID. `DISCORD_EVENTS_CHANNEL_ID` is optional and only adds a separate text message. Its absence does not block draft creation or native publication.

## Implemented workflow

`/dashboard/operations/new`: Location → Event Info → Review → Publish. Voice choices come from the configured guild on the server and persist snowflake IDs. Somewhere Else requires a location and end time. Drafts persist before publication; the publish transaction enqueues a unique native job and, if configured, an independent announcement job. A successful HTTP publish response means queued, not delivered. The detail page polls delivery state and returns `nativeEventUrl` once the worker records the native ID.

The form supports optional covers (PNG/JPEG/WebP under 500 KB, decoded with a 16-megapixel ceiling, re-encoded to JPEG without metadata; no remote image fetching), explicit IANA timezone conversion and DST earlier/later disambiguation. Weekly and fortnightly native recurrence are supported in UTC only. Discord does not accept externally supplied recurrence count/end. Daily/monthly/yearly/custom schedules and local wall-clock recurrence across DST are rejected by this implementation, not approximated. Native series are one Discord resource; separate per-occurrence attendance/commitments remain part of the broader series phase.

Members explicitly commit, tentatively commit, reserve or withdraw on the website with preferences. Discord Interested is neither imported nor used as attendance, assignment or reliability. Capacity/waitlist automation, ships/crew, attendance/AAR and the other comprehensive phases remain incomplete.

## Authorization and privacy

All create/publish/edit/lifecycle/retry/recreate/reconcile mutations use active database accounts and current guild membership/roles through `lib/personnel/policy.js`'s unchanged seven officer IDs. Site Admin, Discord Administrator, owner status and display names do not bypass this gate. Creator/co-managers must still qualify; the current Clan Warlord may manage any operation. All mutation transactions recheck live authority before commit; worker dispatch rechecks the initiating manager immediately before a remote write. Discord/PostgreSQL cannot share an atomic transaction: a small external role-change race remains unavoidable.

HTTP routes use Auth.js, exact Origin checks, the existing write rate limiter, bounded JSON parsing, scoped queries and sanitized errors. Statuses: 400 malformed/oversized body; 401 absent login; 403 current authority/origin denial; 404 scoped/missing record; 409 stale revision/state/conflict; 422 input/channel/permission validation; 429 rate limit; 503 disabled feature/provider outage. Mutations never trust actor, guild or role claims supplied by the browser.

Officer-only operations may be saved as drafts but cannot be natively published. Discord's only native privacy enum is GUILD_ONLY; it does not provide an officer-only event. There are no private notes in the native description. Guild visibility follows Discord's platform rules, including discoverable guild behavior; operators must not put confidential material in guild-wide event descriptions. Optional announcements require a configured guild text channel and effective View Channel, Send Messages and Embed Links. No broad mentions are enabled. Signup buttons are not placed on native cards; this slice uses dashboard signup and a link in the optional announcement.

## Delivery and synchronization

`CommandOperation` owns guild/creator/manager scope, desired fields, revision/state and mapped IDs. `CommandDelivery` has unique operation/revision/kind keys, an actor, leases, attempts, due time and a persisted sending marker. Claiming uses PostgreSQL SKIP LOCKED; operation row locks serialize publication/edits. Leases last 180 seconds, delivery transactions are bounded to 90 seconds, REST requests to 15 seconds. A separate discord.js REST adapter disables automatic POST retries and rejects rate-limit queues so the database controls backoff. Retries are bounded to six attempts, with 429 delay respected. SIGTERM/SIGINT stops claims and drains the in-flight tick; abrupt shutdown is recovered through lease expiry.

Native POST has no nonce/exactly-once guarantee. The operation's deterministic dashboard link is the reconciliation marker. A crash after POST but before recording searches native events for that link, links a unique match and does not create another. Multiple/no matches after an uncertain send become AMBIGUOUS, not blind retries. A newer revision cannot bypass an older uncertain create. The reconcile action only links a unique matching event and opens a conflict review; it never creates another event. An unresolved no-match case requires operator investigation and remains blocked. Optional messages use Discord nonce/enforce_nonce for its limited dedupe window and conservatively flag uncertain sends.

Dashboard edits PATCH the mapped native ID; cancellation changes a scheduled native event to CANCELED, or an active native event to COMPLETED because Discord does not support ACTIVE → CANCELED. The website retains CANCELLED. Ending does not finalize attendance. Terminal native events cannot be restarted. An existing Discord end time cannot be cleared; choose a replacement end time.

The worker polls mapped scheduled/active operations every 15 seconds (up to 100 records, matching Discord's active/scheduled guild cap). Interested counts are excluded from snapshots. Different remote briefing/location/time/recurrence/cover/status values produce a CONFLICT snapshot. An officer reviews then explicitly adopts supported remote fields or reapplies the dashboard version. Adoption enqueues no native write, preventing loops; adopted covers remain remote unless the officer explicitly replaces/removes them. Unsupported remote schedules stay conflicted. Deletion sets DELETED and does not recreate. The explicit recreate action requires current management authority, increments the revision, audits the prior ID and queues a new create. Unknown message/native outcomes are visible, never silently called published.
